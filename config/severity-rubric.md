# 심각도 기준

모든 리뷰어가 같은 기준으로 판정해야 이슈 목록의 우선순위가 의미를 가집니다. 애매하면 **한 단계 낮게** 잡으세요. 과장된 심각도는 리뷰어에 대한 신뢰를 떨어뜨립니다.

| 등급 | 기준 | 예시 |
|---|---|---|
| critical | 인증 우회, 타인 데이터 접근, 데이터 손상·유실, 원격 코드 실행 가능 | 인가 체크 없는 다운로드 API, 경로 조작으로 임의 파일 읽기, SQL 인젝션 |
| high | 정상 사용 흐름에서 오동작이 재현 가능 | NPE로 팩스 발송 실패, 트랜잭션 누락으로 부분 저장, 정렬 파라미터 검증 누락 |
| medium | 특정 조건에서만 문제가 되거나, 유지보수 비용을 확실히 늘리는 구조 문제 | 도메인 경계 위반(baseline 외 신규), 예외 삼킴, 중복 로직 3곳 이상 |
| low | 개선하면 좋은 제안 | 명명 불일치, 작은 중복, 불필요한 추상화 |

## 이슈로 등록하지 않는 것

- 스타일, 포매팅 취향 (린터 영역)
- 근거 코드 위치를 특정할 수 없는 추측
- `domain-boundary-baseline.txt`에 이미 등록된 기존 위반. baseline은 줄이는 대상이지 신규 발견이 아닙니다. 줄이기 제안은 refactor로 한 번만 등록합니다.
- 테스트 코드의 사소한 문제
